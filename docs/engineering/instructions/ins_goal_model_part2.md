## 1. 成長ビューへのゴールライン+進捗軸統合

- 部位のe1RM推移グラフに**ゴールライン**(targetE1Rm・最新体重で都度計算)を水平描画。視覚仕様は5b handoff §5が正
- グラフ下または部位カードに**進捗軸表記「N% ・ あとNkg」**(goalProgressの結果)。スタートマーカーも5b仕様どおり
- **指標乖離ルール(前半確認事項2の帰結)**: 成長ビューの基準種目が**レップ指標(ISS-018)の部位では、ゴールラインをグラフに描かない**(kg線をレップ軸に重ねない)。進捗軸表記(e1RM基準種目由来)は表示してよいが、その場合「基準: ◯◯(種目名)」を進捗軸側に併記して、グラフと別種目基準であることを明示する
- ゴール未設定の部位は現行表示のまま(ライン・進捗軸なし)
- 到達済み(状態4)・維持(状態5)の色表現は5b handoffの状態定義に従う(維持=鋼色・グローなし)

## 2. 到達判定と鏡チェックフロー

### 判定タイミング
- セッション記録保存時に、記録部位のうち `mode==='growth'` かつゴール設定済みの部位について `currentE1Rm >= targetE1Rm` を判定
- 到達を検知したら `goal_events` に `reached` を記録(同一部位で判定未消化のまま再到達しても重複記録しない)

### 到達演出(セッション後サマリー)
- PR演出に準ずる熱さ(5b handoff・emberPulse)。文言: 「**◯◯がゴールに到達しました。鏡を見て判定してください**」
- サマリー上でそのまま判定可能にする。判定選択肢:
  - **満足** → `mode='maintain'` に更新+`goal_events`に`maintain`記録。以後の生成は前半実装済みの維持調整が効く
  - **物足りない** → レベルを1段引き上げ(`toned→solid→big`)+`goal_events`に`raise`記録。**bigで物足りない場合**は直接編集モーダルを開き、現目標+10%を初期値として提案(Elite係数は採用しない・DEC-013)
  - **あとで判定** → 何もしない(状態4のまま残留)

### 未消化の到達(あとで判定)
- 設定画面のゲージ行が状態4のまま残る(前半で表示実装済み)。**行タップで同じ判定モーダル**を開けるようにする(前半でスタブだったタップ遷移を接続)
- ダッシュボードへのバッジ追加はv1スコープ外(欲しくなったらISS)

### 維持からの復帰
- 設定画面で維持中の部位のレベルを変更(またはノッチ再タップで確認ダイアログ)したら `mode='growth'` に戻す+`goal_events`に`resume`記録。1行導線で十分(凝らない)

## 3. データ

- 新テーブル `goal_events`: `{ id++, muscle, type: 'reached'|'maintain'|'raise'|'resume', at: Date, note?: string }`(構想§2-5のSSOT的追跡)。バックアップ対象に追加
- `muscle_goals` に `reachedAt?: Date` を追加(状態4判定の高速化用。判定消化時にクリア)
