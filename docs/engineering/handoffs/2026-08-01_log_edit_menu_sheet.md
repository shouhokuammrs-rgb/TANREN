## ISS-020: ログの事後編集

### 実装
- **LogDetailPage「記録を編集」モード**: セットごとに±ステッパーで即時保存(weightは0.5kg刻み・repsは1刻み・下限は正の値。Dexie liveQueryで再描画)。自重セット(weight実績なし)はrepsのみ。未実施セットは削除のみ可
- **セット追加**: 種目カード下の「+ セット追加」で直近の完了セットを複製して末尾に追加(完了扱い・setNumber連番)
- **セット削除**: ✕ボタン。残りセットのsetNumberを1から詰め直す。**最後の1セットの削除は種目記録ごと削除**(確認ダイアログ)
- **achieved再判定**: 編集時は記録時(`recordSet`)と同一規則で再計算(提案以上=達成)。派生値(e1RM・成長点列・ゴール進捗・状態4導出)は純関数のため自動反映——再計算コードは追加していない
- **遡及再判定なし(v1・INS準拠)**: PRバッジ(`isPr`)・`goal_events`は書き換えない。到達イベントは次の`finishSession`判定に委ねる
- **編集済み表示**: `Session.updatedAt`(新規任意フィールド・マイグレーション不要)で判定し、ステータス横に控えめに表示。バックアップのDate復元対象に追加済み
- **クラウドバックアップ**: 編集のたびに`CLOUD_PENDING`を立て(次回起動の`retryPendingCloudBackup`が拾う)、「編集を終える」タップ時に`autoCloudBackup()`を発火(未ログイン時はno-op)

### スコープ外(INSどおり)
種目の追加・セッション日時変更はなし(セッション削除は既存ISS-008のまま)

## ISS-021: 実行画面のメニュー一覧シート

### 実装
- **ヘッダー☰ボタン**(44pxターゲット・SETチップ横)→ 既存Modal(ボトムシート)流儀で全メニュー表示
- **行**: 種目名・目標セット×レップ・重量提案(自重は「自重」)・完了数`n/N`・状態チップ(✅済=achieved色 / ▶実施中=molten+ember背景 / 未=鈍色・行全体50%減光)
- **状態導出**: `utils/workoutMenu.ts`の純関数`entryStatuses`(全セット完了=済/最初の未完了セットを含む種目=実施中——実行画面の`firstIncomplete`と同じ規則/以降=未)。メニュー生成結果+実績の突合のみで**新規テーブルなし**
- **タイマー非停止**: シートはRESTINGのtick(useEffect interval)と独立したstateのため、表示中もカウントダウン・3秒ビープ・準備アラーム(残20秒)は動き続ける
- **参照のみ**: 行タップのジャンプ・順序入替はスコープ外(INSどおり)

## PM確認事項(実装で解決せず記載)

1. **編集UIの操作系**: 数値直接入力ではなく±ステッパー(即時保存)としました。実行画面のHeroStepperと同じ操作感を優先した裁量です。大幅な修正(例: 8→20レップ)はタップ回数が増えるため、不便なら直接入力の追加をISSで
2. **未実施セットの扱い**: 編集モードでは削除のみ可(実績がないため値編集は不可)としました。「未実施→実施済みに変える」導線はスコープ外の解釈です
3. **編集済み表示の粒度**: セッション単位(ステータス横に1つ)です。セット単位のマークは保持しない仕様(編集履歴なし)に合わせました
4. **メニューシートの重量表示**: 現在(=最初の未完了)セットの提案値を表示しています(全完了種目は先頭セット)。セットごとに提案が異なる場合に代表値1つになる点はご了承ください
