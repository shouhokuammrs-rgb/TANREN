## 実装内容

### §1 成長ビューへのゴールライン+進捗軸統合
- e1RM推移グラフ(カード+フルスクリーン)に水平ゴールライン: `#FFE3CC` 1.5px実線+右端に値タグ(`#FFE3CC`塗り・角丸3px・Mono 700 10px `#0B0907`)。Y軸domainは目標値を含むよう拡張
- カードヘッダー右に進捗軸 `{進捗率}% ・ あと{残り}kg`(Mono 700 12px `#FFE3CC`・`goalProgress`由来)
- **指標乖離ルール**: 基準種目がレップ指標(ISS-018)の部位ではゴールラインを描かない(`chartGoalLineKg`が純関数で判定)。進捗軸は表示可・その場合「基準: ◯◯(種目名)」をカード内に併記(`goalTrendByMuscle`が基準種目名を返すよう拡張)
- ゴール未設定部位は現行表示のまま。維持(状態5)部位は人体図を鋼色`#C9B79C`フラットに置換(グローなし・熱スケール外)。ダッシュボードのミニ人体図にも同適用

### §2 到達判定と鏡チェックフロー
- `finishSession`が`recordReachedGoals`を呼ぶ: 記録部位×growthゴール×判定未消化(`reachedAt`なし)について `currentE1Rm >= targetE1Rm` を判定(境界`==`も到達)。到達で`reachedAt`セット+`goal_events`に`reached`(未消化のままの再到達は`detectReachedGoals`が抑止=重複記録なし)
- サマリー到達カード: 金色`#FFB300`+emberPulse+🏆「◯◯がゴールに到達しました/鏡を見て判定してください」。その場で判定3択:
  - **満足** → `mode='maintain'`+`reachedAt`クリア+`maintain`イベント。維持調整(種目1・セット−1・2ステップ不適用)は前半実装が効く
  - **物足りない** → レベル1段上げ(プリセット係数)+`raise`イベント。**big到達時**は+10%提案値(0.5kg刻み)入りの直接編集を開き、係数化保存(Elite係数不採用・DEC-013)+noteに編集kgを記録
  - **あとで判定** → 何もしない(状態4残留)
- 設定画面: 状態4を`reachedAt`駆動に変更し、行タップで同じ鏡チェックモーダル(前半のスタブ遷移を接続)。未編集時はDB変化(判定結果)をドラフトに自動追従
- 維持からの復帰: 維持中部位のノッチタップ→確認ダイアログ→`mode='growth'`+`resume`イベント(即時反映)

### §3 データ
- Dexie v5: `goal_events { id++, muscle, type: reached|maintain|raise|resume, at, note? }`。`muscle_goals.reachedAt?: Date`(状態4マーカー・判定消化でクリア)。両方バックアップ(エクスポート/インポート/全削除/クラウド)対象に追加

## PM確認事項(実装で解決せず記載)

1. **到達検知のタイミング**: `finishSession`(トレ終了保存)のみで判定し、中断保存(`abortSession`)では判定しません。「セッション記録保存時」の解釈ですが、中断でも判定すべきなら1行で追加できます
2. **維持部位の成長ビュー表示**: 5b §5は維持=鋼色置換のみ明記のため、維持部位では**ゴールライン・進捗軸を非表示**にしました(成長を追う表示は growth モード限定)。維持中もライン等を出したい場合は要調整
3. **維持復帰の即時反映**: 復帰は確認ダイアログOKで即DB反映(保存CTAを介さない)としました。「1行導線で十分」の解釈です
4. **ミニ人体図への適用**: ダッシュボードの成長カード(4b)人体図にも維持=鋼色を適用しました(同じ`growthPaint`共用のため一貫)。成長ビュー限定が意図なら戻します
5. **サマリー到達カードの残留**: 「あとで判定」後もサマリーを再訪すると判定未消化カードは表示されたままです(状態4の残留表現として意図的)
