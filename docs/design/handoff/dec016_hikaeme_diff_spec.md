# DEC-016 差分仕様 — ゴールプリセット第4段「ひかえめ」

`docs/design/handoff/5b_goal_model_handoff.md` への差分。本書に書かれていない項目はすべて既存5b仕様のまま。
DEC-016趣旨: **服を着ていれば全く分からない、健康維持レベル。既に超えている部位なら即到達→維持で「これ以上大きくしない」抑制運転。**

## 1. 係数表(4段・Strength Level Beginner追加)

| 部位 | **ひかえめ** | 引き締め | しっかり | がっつり |
|---|---|---|---|---|
| 胸 | **0.20** | 0.35 | 0.50 | 0.70 |
| 背中 | **0.20** | 0.35 | 0.55 | 0.75 |
| 肩 | **0.15** | 0.25 | 0.40 | 0.55 |
| 腕 | **0.10** | 0.15 | 0.30 | 0.50 |
| 脚 | **0.15** | 0.25 | 0.40 | 0.60 |

- ひかえめは全部位・全体重域(40–120kg)でcapped(>33.6kg)にならない(最大でも胸0.20×120=24kg)
- レベル順序: **ひかえめ → 引き締め → しっかり → がっつり**(鏡チェック「物足りない」の1段上げもこの連鎖)

## 2. ① ゲージのノッチ4個化

### 2-1. ルール(変更なしの明記)

- X座標正規化は既存のまま: `maxV = max(がっつり目標, 33.6) × 1.14`、`x = min(97, 値/maxV×100)%`
- ノッチ寸法・状態表現も既存のまま: 18×18円・`top: 4px`・`margin-left: -9px`・枠2px・選択レベルのみ点灯+グロー
- 上限帯・スタート/現在地マーカー・進捗フィルへの影響なし
- ひかえめノッチは各ゲージの最左に追加されるのみ(係数が小さいため4ノッチ中3つが左半分に寄るが、これは「がっつりまでの距離」を見せる本UIの主張どおりで調整しない)

### 2-2. 腕(0.10〜0.50)の視認性・タップ性検証

最タイトなのは**腕の第1(ひかえめ)↔第2(引き締め)間**。トラック実効幅326px(390px画面・ページ余白16×2+行padding16×2)での中心間隔の実測:

| 体重 | ノッチX座標(%) | 第1↔第2間隔 | 判定 |
|---|---|---|---|
| 40kg | 10.4 / 15.7 / 31.3 / 52.2 | **17.0px** | 18px円が1px接触 |
| 42.3kg | 11.0 / 16.6 / 33.1 / 55.2 | 18.0px | ちょうど接する(境界) |
| 45kg | 11.7 / 17.6 / 35.2 / 58.7 | 19.1px | 分離 |
| 58kg(現Owner) | 15.1 / 22.7 / 45.4 / 75.7 | 24.7px | 問題なし |
| 70kg以上 | 17.5 / 26.3 / 52.6 / 87.7(比率一定) | 28.6px | 問題なし |

参考: 他部位の最小間隔(58kg時)は脚47.7px・肩49.4px・背中57.2px・胸61.3px — 腕以外は余裕。

### 2-3. 裁定

1. **ノッチは18px据え置き・特別対応なし**。接触が起きるのは体重42.3kg未満のみで、体重ステッパーの下限40kgのごく近傍に限られる(Owner実測域58kg前後では24.7px確保)
2. タップは現行どおりノッチごとの独立ボタンで分割されるため、接触時も機能は壊れない。**選択中ノッチを最前面(z-order)にする**ことだけ追加(接触時に点灯ノッチが下に隠れないように)
3. タップ領域の44px拡張は**行わない**(隣接間隔が44px未満のため拡張すると誤タップが増える)。実機で指先精度が問題になったらISSで別途(候補: ノッチ下にレベル名チップ列)

## 3. ② 「ひかえめ」の生活言語説明文(5部位)

既存キャプション表に行追加。見た目に出ないレベルのため、**見え方ではなく日常機能の言葉**で書く(趣旨「服を着ていれば全く分からない」と整合):

| 部位 | ひかえめ |
|---|---|
| 胸 | 見た目は変わらない。押す力が日常で衰えない |
| 背中 | 猫背に戻らない。座り仕事の一日に耐える背中 |
| 肩 | 高い棚への上げ下ろしが苦にならない |
| 腕 | 重い買い物袋を平気で持ち帰れる |
| 脚 | 階段と立ち仕事で疲れない土台 |

トーン注記: 既存3段は「見え方」の文、ひかえめのみ「機能」の文になるのは意図的(このレベルの価値は見た目でなく健康維持のため)。

## 5. 挙動差分 — 既超過部位の「即到達」(要PM裁定1点)

DEC-016趣旨の「既に超えている部位なら**即到達**→維持」について。現行の到達検知は**セッション保存時のみ**のため、ひかえめを設定して保存しても、その部位を次に記録するまで状態4にならない(抑制運転の開始が遅れる)。

**提案**: ゴール保存時にも到達判定を追加する — `saveMuscleGoal` はISS-019で既に「現在e1RM vs 新目標」を計算済みのため、**現在 ≥ 新目標 かつ reachedAt未設定なら reachedAt を立てて `goal_events` に `reached` を記録**する1分岐を足すだけで実現できる(重複抑止・判定フローは既存のまま)。これによりひかえめ設定→保存→即サマリー相当の状態4→鏡チェック「満足」→維持、の抑制運転が設定当日から始まる。

採否のみ裁定ください(不採用なら現行どおり「次回その部位を記録したセッション保存で到達」となり、趣旨文の「即」だけが実態と少しずれます)。

## 6. 実装ノート(INS化の材料)

- データ移行: 不要(レベル追加のみ・既存レコード無変更)
- テスト観点: 4段連鎖のnextGoalLevel/ひかえめ係数の目標計算/腕ノッチ4個の描画とX座標(42.3kg境界)/鏡チェック1段上げ(light→toned)/(§5採用時)保存時即到達のイベント記録と重複抑止
