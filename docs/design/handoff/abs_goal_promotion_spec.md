# 腹の段位型ゴール + 昇格提案UI 差分仕様(DEC-017 / DEC-018)

発行: Designer / 2026-08-02(**改定版** — 直列ラダー前提の初版を差し替え)
プレビュー: `docs/design/腹ゴールと昇格UI.dc.html`
接地: `src/components/GoalGaugeSection.tsx` / `src/engine/progression.ts` / `src/db/types.ts` / `src/constants/copy.ts`(main @67f3596 確認済み)
既存仕様: `docs/design/handoff/5b_goal_model_handoff.md`(ゲージ本体)/ `handoff/6b_ia_handoff.md`(IA)

## 0. 改定の要点

オーナー指摘により、**クランチとレッグレイズは並行実施される強調バリエーション**であり、直列のラダーではない。したがって:

- 昇格提案は「**クランチ上限 → ダンベルクランチ(加重)**」の1パターンのみ。クランチ → レッグレイズの提案は作らない
- レッグレイズは上限到達で頭打ち。**提案は出さず、状態表示のみ**
- 段位は階段ではなく「**条件の充足が順不同で積み上がる**」構造

**共通ループは変更なし:** 到達 → 鏡チェック → 維持(鋼色)/ 引き上げ は他5部位と同一。`MirrorCheckModal` / `reachedAt` / `goal_events` / `GoalMode` をそのまま使う。

## 1. 昇格提案UI(DEC-017)

### 1-1. 置き場所 — セッション後サマリー

実行画面には出さない(スコープ外であり、セット loop の途中に選択を挟まない)。
サマリーは既にPR演出・ゴール到達カード・鏡チェックを載せる「振り返って決める」場なので、ここに合流させる。

**表示順(サマリー内):** 総ボリューム → **昇格カード** → PRカード → ゴール到達カード → 種目リスト → 保存CTA

昇格カードとゴール到達カードが同時に出る場合、昇格カードを上に置く(種目が変わる話が先、身体の判定が後)。

### 1-2. 発火条件 — クランチのみ

`suggestWeightReps` の自重分岐(`progression.ts`)— **自重種目で `allAchieved && minReps >= repRangeMax`、かつ `anyAtFailure === false`** のとき現行は `{ reps: repRangeMax }` を返して頭打ちになる。この分岐が提案のトリガー。

| 種目 | 上限到達時の扱い |
|---|---|
| **クランチ** | 昇格カードを出す(→ ダンベルクランチ) |
| **レッグレイズ** | **カードを出さない。**頭打ちのまま継続。成長タブに状態表示のみ(§4-1) |
| ダンベルクランチ | 出さない。通常の重量増量ループ(DEC-007)に乗っているため |

- 判定はセッション保存時に1回。カードは常に1枚
- 昇格しても**レッグレイズは献立から外さない**(並行種目のため)。カード本文にもその旨を書く

### 1-3. カード構成

| 要素 | 仕様 |
|---|---|
| 枠・背景 | `border-molten` 1px / `bg-[rgb(255_92_26/.07)]` / `rounded-card` / `anim-rise` |
| ラベル | 「腹 — 重りを足す」`label-mono text-[10px] text-molten-bright` / 右に「自重 → 加重」`text-ink-dim` |
| 見出し | 「クランチが3セットとも上限に届きました」Noto 900 17px `text-ink` |
| 対比ブロック | 左「いま クランチ / 自重 20回 × 3」(枠 `line-ember`)→ 矢印 → 右「次 ダンベルクランチ / 2.5kg・8回から」(枠 `molten`) |
| 説明 | 「回数を増やし続けるより、重りを持つ方が伸びます。時間は変わりません。**レッグレイズはそのまま続きます。**」Noto 400 12px `text-ink-mid` |
| 受諾 | `pill-molten` 「ダンベルクランチに進む」 |
| 見送り | `pill-ghost` 「まだ自重で続ける」 |

**文言方針:** 鍛錬メタファーを使わない(DEC-005以降の方針)。「卒業」「昇格」は内部用語に留め、UIには出さない。ユーザーに見せるのは種目名・重量・回数だけ。

### 1-4. 受諾 / 見送り

| 操作 | 挙動 | フィードバック |
|---|---|---|
| **受諾** | 次回メニュー生成からクランチをダンベルクランチに差し替え(レッグレイズは維持)。クランチのログは残す | 枠 `molten`:「ダンベルクランチに切り替えました / 次回のメニューから入ります。2.5kg・8回で再開し、以降は通常の増量に乗ります。」 |
| **見送り** | 現状維持。**次に同じ条件で上限を達成した回に再提案** | 枠 `steel-line`・`text-steel`:「自重のままにしました / 次にまた上限を達成したときに、もう一度おすすめします。」 |

- 見送り回数の上限は設けない(オーナー主権。うるさく感じたら ISS で調整)
- 押下後はボタン2つを確認ブロックに置換。同一サマリー内での取り消しはしない

### 1-5. 回 → kg 切替時の成長ビュー注記

ダンベルクランチへ移ると、クランチ系列の指標が **最大レップ(回・ISS-018)から e1RM(kg)** に変わる。同じ折れ線に連続して描くと誤読を生むため系列を分ける。

| 要素 | 仕様 |
|---|---|
| 切替点 | 縦の破線(`#3A2213` 1px `dasharray 4 4`)を切替セッションの位置に |
| 回の系列 | `#8A5A3C` 2px・ドットなし(過去の参考として残すが主役から降ろす) |
| kgの系列 | `molten` 2.5px + `drop-shadow(0 0 6px rgb(255 92 26/.5))` + `text-hot` のドット |
| 軸ラベル | 左「回(クランチ)」右「↑ ここからkg(ダンベルクランチ)」`label-mono text-[9px]` |
| 注記 | 「加重に移ったため指標が『回』から『kg』に変わりました。前後の数値は直接つながりません。」Noto 400 10px `text-tab-idle` |

- **進捗軸は新系列で再計算**。スタート = 加重初回セッションの e1RM。回時代の値は混ぜない
- 変化率(%)も切替をまたいで計算しない。切替直後は「データ不足」(既存の3セッション未満ルール)
- **レッグレイズの系列は別扱い**。回のまま継続し、切替の影響を受けない

## 2. 腹の段位ゴール(DEC-018 改定版)

### 2-1. 段位の定義 — 条件の充足で決まる

条件は3つ。**順不同**で積み上がる。

| 条件 | 内容 |
|---|---|
| C1 | クランチが `repRangeMax` × 全セット(自重) |
| C2 | レッグレイズが `repRangeMax` × 全セット(自重) |
| C3 | ダンベルクランチが `repRangeMax` × 全セット(加重・2.5kg〜) |

| 段位 | 到達条件 | 生活言語キャプション |
|---|---|---|
| **引き締め** | C1 または C2(**自重どちらか**) | 腹に力を入れると硬さがわかる |
| **しっかり** | C1 かつ C2(**自重2種目とも**) | 力を抜いても腹の中央に縦線が出る |
| **がっつり** | C3(**加重で上限**) | 普段の姿勢でも段の区切りが見える |

導出(実装の述語):

```
attained = C3 ? 'big' : (C1 && C2) ? 'solid' : (C1 || C2) ? 'toned' : none
```

- **ひかえめ(DEC-016)は腹に作らない。**3段のまま。自重未クリアが実質の下限で、4段目に対応する実体がない
- 段位は離散量のため**進捗率(%)を出さない**。偽の精度になる

### 2-2. 設定①での置き場所

`GoalGaugeSection` のゲージ行×5 の**直後**に腹の行を追加(表示順: 胸・背中・肩・腕・脚・腹)。
`GOAL_TARGET_MUSCLES` は5部位のまま維持し、腹は**別コンポーネント(`AbsGoalRow`)**として並べる — 係数軸を持たないため `GOAL_COEF` / `targetE1Rm` / `isCapped` の経路に載せない。

行の外形は5bゲージと共通にして「並んでも違和感がない」ことを担保する:

| 揃える | 値(既存 `GoalGaugeRow` と同一) |
|---|---|
| コンテナ | `rounded-card px-4 py-3` / 枠1px / 状態別 border・background |
| 1段目 | 部位名(Noto 700 13px `text-ink`)+ 右に段位(`label-mono text-xs font-bold`) |
| 2段目 | 高さ **26px** の領域(ゲージのトラックと同じ) |
| 最終段 | 生活言語キャプション(`border-t border-[#1A110B] pt-1.5 text-[11px] text-ink-dim`) |

### 2-3. 2段目 — 段位バッジ(ゴール選択)

```
[ 引き締め ][ しっかり ][ がっつり ]      ← 高さ26px・gap 6px・flex-1 均等
 自重どちらか 自重2種目とも  加重で上限     ← 8px Mono の条件キャプション
```

**階段状にしない。**5bのノッチは連続量の上の点だが、こちらは独立した3つの到達条件なので、**連結せず gap 6px で切り離し、角丸は3つとも同じ8px**にする。これが「順不同」を造形で示す唯一の手段。

| 状態 | 枠 | 背景 | 文字 |
|---|---|---|---|
| **選択中(ゴール)** | `molten` 1.5px | `rgb(255 92 26/.10)` | `text-hot` |
| **到達済み** | `steel-line` 1.5px | `rgb(201 183 156/.06)` | `steel` + 先頭に `✓` |
| **未到達** | `#241812` 1.5px | transparent | `tab-idle` |

- 選択中のみ `box-shadow: 0 0 10px rgb(255 92 26/.35)`(ゲージのノッチ `.6` より弱く。面積が大きいため)
- タップでゴール段位を変更。**到達済みの段位も選択できる**(下げる = 抑制運転。DEC-016 のひかえめと同じ考え方で、選択後すぐ到達 → 鏡チェック → 維持に入る)

### 2-4. 3段目 — 条件チェックリスト

段位バッジの下に、3条件の充足状況を並べる。**これが進捗表示の本体。**

| 要素 | 仕様 |
|---|---|
| 行 | 枠1px / `rounded-[8px]` / `px-2.5 py-1.5` / 縦 gap 5px |
| チェックボックス | 15×15px / `rounded-[4px]` / 枠1.5px。充足時: 枠・塗り `steel` + `✓` を `forge-black` で |
| 種目名 | Noto 700 11px。充足 `steel` / 未充足 `ink-dim` |
| 右端 | 「自重 20回 × 3」`label-mono text-[9px]`。充足 `steel-line` / 未充足 `#4A3A2C` |
| 充足済みの行 | 枠 `steel-line` / 背景 `rgb(201 183 156/.07)` |
| 上限到達で頭打ち中の行 | 枠 `#8A431C`(レッグレイズが上限のまま継続している状態を静かに示す) |

3条件の下に1行:

- 左: 「条件は順不同。どの種目からでも積み上がります」Noto 400 9px `#6B5A4C`
- 右: 選択中ゴールへの充足数 —「自重 1/2 種目」「加重 0/1 種目」。到達済みなら `MUSCLE_GOAL_COPY.reached`(「達成 — 判定待ち」)を流用し `#FFB300`

**段数表記の統一:** 「n/3 段クリア」という表現は改定で廃止(積み上がり順が一定でないため)。到達段位は**段位名**で表す(「引き締め 到達」)。設定①・成長タブとも同じ語で出す。

### 2-5. データ

`MuscleGoal` をそのまま使う。`muscle: 'abs'`、`level: 'toned' | 'solid' | 'big'`、`coef` は**未使用(0固定)**。
`GoalMode` / `reachedAt` / `goal_events` は他部位と同一の扱い。

- `isGoalTargetMuscle()` は5部位判定のままにし、腹は別の判定関数(`isAbsGoal` 等)で分岐 — 係数計算の経路に腹が混入しないように
- 到達検知は e1RM 比較ではなく**条件充足の再評価**で行う(セッション保存時に C1/C2/C3 を判定 → `attained` が選択ゴール以上なら `reachedAt` を立てる)

## 3. 体脂肪率の入力(DEC-018 補助軸)— 依頼どおり変更なし

### 3-1. 置き場所 — 体重ステッパーと同じカード内・下段

別モーダルにはしない(週次操作を1タップ増やさない)。ただし体重と同じ視覚的重さにもしない — **体重は目標に直結する必須値、体脂肪率は任意の参考値**という差を階層で示す。

既存の体重ステッパーカード(`rounded-[12px] border-[#241812] px-3.5 py-2.5`)の中に区切り線 `border-t border-[#1A110B]` を引いて1行を追加:

| 状態 | 表示 |
|---|---|
| **未入力・閉** | 左「体脂肪率(任意)」Noto 400 11px `tab-idle` / 右「— ✎」`label-mono text-xs text-accent-dim` |
| **入力済み・閉** | 右「17.2% ✎」 |
| **開** | −/+ ステッパー(**0.1%刻み**・範囲 3.0〜60.0)。ボタン32px円形・タップ領域44px。値は Anton 26px `text-hot`。下に「体組成計の値でOK。同じ計器で続けて測るとトレンドが見えます」Noto 400 9px `#4A3A2C` |

### 3-2. 保存

`BodyStat` は**既に `weightKg?` / `bodyFatPct?` を持っている**(`src/db/types.ts`)。新規フィールド追加ではなく**既存フィールドの利用**であり、**スキーマ変更・マイグレーションは不要**。

保存CTA(「ゴールを保存」)押下時、体重と体脂肪率を**1レコードにまとめて** `body_stats` へ書く(`addBodyWeight` を体脂肪率も受け取れるよう拡張)。片方だけの変更でも1レコードで良い。

`Profile.bodyFatPct` はセットアップ時の初期値として残し、トレンドは `body_stats` 側を正とする。

## 4. 腹詳細の2軸表示(成長タブ)

成長タブで腹を選んだときの詳細。**上下に分離**し、意味色を混ぜない。

### 4-1. 上: 厚み(段位)

- カード: `card-ember`(`bg-ember-tint` + `border-line-ember` + `rounded-card`)
- ヘッダー: 「厚み — 段位」`label-mono text-molten-bright` / 右に**到達段位名**(「引き締め 到達」/ 未到達なら「未到達」)`text-hot`
- 段位バッジ3つ(§2-3 と同一造形。ここでは**表示のみ・タップ不可**)
- 区切り線の下にクランチ系列の推移グラフ(§1-5 の回→kg切替仕様を適用)
- **レッグレイズの状態表示**(提案は出さない): グラフの下に1行 —「レッグレイズ / 18回で上限 — このまま継続」。左 Noto 700 11px `ink-dim`、右 `label-mono text-[10px] text-tab-idle`。CTAもグローも付けない

### 4-2. 下: 薄さ(体脂肪率トレンド)

- カード: 枠 `#241812` 1px(`card-ember` より弱く。**参考値であることを地の色で示す**)
- ヘッダー: 「薄さ — 体脂肪率トレンド」`label-mono text-ink-dim` / 右に最新値 `text-ink-mid`
- 折れ線: `#D9CFC6` 2px + 同色ドット。**溶鉄を使わない** — 体脂肪率の低下は「成長」ではなく別軸の変化であり、熱スケールの意味体系に載せない
- Y軸は上が高値(体脂肪率が下がると線が下がる)

### 4-3. 目安ライン(断定的に見せない)

| 項目 | 仕様 |
|---|---|
| 線 | `#8A5A3C` 1px `stroke-dasharray="3 5"` `opacity .7`。**実線にしない・グローを付けない** |
| 位置 | ≈15% / ≈12% / ≈10% |
| ラベル | 「うっすら ≈15% 目安」「割れ目 ≈12% 目安」「くっきり ≈10% 目安」— `label-mono text-[9px] text-ink-dim`。**`≈` と「目安」を必ず併記。ラベルなしの水平線は『超えるべき閾値』に読めるため、線とラベルは常にセット** |
| ラベルの実装 | チャートSVGの外に**HTMLで**絶対配置する(右端・線のY位置に `translateY(-50%)`・背景色付きの小パディングで線と重ねる)。SVG `<text>` は使わない — グラフが `preserveAspectRatio="none"` で横に伸縮するため、内部のグリフが非等方に潰れる |
| 到達演出 | **なし。**線を下回っても色は変わらず、通知もPR演出も出さない |
| 注記(必須・カード内に常設) | 「破線は一般的な見え方の**目安**で、達成すべき数値ではありません。体組成計の絶対値は誤差が大きいため、同じ計器で測った変化の向きだけを見てください。」Noto 400 10px `text-tab-idle` |

- 体脂肪率が未入力、または測定が3点未満のときは**カードごと非表示**(段位だけを出す)。空グラフを見せない

## 5. 実装メモ

- 新規コンポーネント: `AbsGoalRow`(設定①)/ `AbsDetail`(成長タブ)/ `PromotionCard`(サマリー)
- 文言はすべて `src/constants/copy.ts` に追加(`ABS_GOAL_COPY` / `PROMOTION_COPY` を新設)。UI側にリテラルを置かない
- `GOAL_COEF` / `GOAL_TARGET_MUSCLES` は変更しない。腹は別経路
- 条件 → 種目の対応は `src/constants/goals.ts` に `ABS_CONDITIONS` として定義(種目IDで持つ)。**順序を持つ配列として扱わない**(表示順のみ)
- ダンベルクランチは新規種目のためシード追加が必要(`primaryMuscle: 'abs'` / `movementPattern: 'core'` / `requiredEquipment: ['dumbbell']`)
- 条件充足の判定と昇格提案の発火は同じ述語を共有できる(`isCapReached(exercise, lastEntry)`)。二重に書かない — ただし**提案を出すのはクランチのみ**という分岐は提案側に置く

## 6. 未確定・確認したい点

1. **ダンベルクランチの `repRangeMin/Max`** — がっつりのクリア条件が `repRangeMax` 依存のため、シード値の決定が必要
2. **昇格を見送り続けた場合の扱い** — 現案は毎回再提案。うるさければ「3回見送ったら以降は設定からのみ」に変更可
3. **腹の到達検知タイミング** — 他部位は e1RM 更新時。腹はセッション保存時の条件再評価になるため、鏡チェック通知の出るタイミングが1テンポ違う可能性
4. **加重に移った後のクランチ(自重)の扱い** — C1 の充足は維持されるか(=一度クリアした条件は落ちないか)。現案は「落ちない」前提

## PM裁定(2026-08-02)

§6-4 **採用**: 一度クリアした条件(C1/C2/C3)は落ちない。段位=チェックポイントの思想と一貫し、実装上も加重移行後に自重データが停止するため導出再判定は不成立。条件クリアは達成イベントとして永続保存する(INS参照)。その他全項承認。
